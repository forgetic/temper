# Agent protocol checkpoint

`tools`, `render` and `translate` own the provider tool vocabulary, bounded
JSON grammar, UTF-8-safe result text and ordered opaque replay. Request
admission measures the final dialect document before allocating its body.
The existing agent domain world uses these production functions through a
small neutral fake-query mapping; that domain-tier mapping preserves its
max-token and cache-write budget semantics and does not claim provider-wire
conformance.

`payload` decodes the current engine charter schema and resolves its models
against the complete indexed endpoint table. Only used LLM accounts enter
the credential scope. The current run vocabulary supports Change, Report
and Verdict; report growth/plans and Turn/resume policy remain deferred.
Channel snapshot bytes cause typed Unsupported rather than an invented
resume policy. The deployment supplies Anthropic identity fragments; this
crate makes no fresh client-identity or live-provider conformance claim.

`channel` operates the real full-duplex `temper-channel` frame machine.
An owner supplies repository roots, routes `Up::Below` to actual lower
owners, and calls `closed` only when the real pipes settle. A frame fault
requires the owner to begin lower closure. Binding retirement, root/process
creation and TLS are separate unavailable skein integrations. Agent links
have an opening timeout and credential-expiry cleanup, with no ping or
silence/stall policy. The constructor checks its memory bound and compares
the actual domain `limits.skew` with protocol skew.

The scheduler uses request-aware `can_take`; cleanup and delayed local
admission remain routable after Failed/Closed. Content is popped only while
`can_fact` allows both byte and record reserves. Content-free shape facts
can be held in one owner slot for `can_take_fact`; ordinary blocked facts
are counted/dropped. CheckFinished is consumed metadata, because it can be
dropped or delayed by the domain queues.

The future actual Check/Abort owner must call `begin_check` with its fresh
generation-bearing operation token before running the operation, then
`end_check` with that same token only after actual settlement and before
delivering Checked/Aborted to the domain. This token belongs to the io
owner and differs from a reusable domain Call token. Stale/duplicate
settlements are fenced; one owed LongDone stays ordered after Long and
before the next Long/Finish. This is a lifecycle hook, not an implemented
process/watchdog integration.

The v1 Finish schema has no refusal or spend fields. `worker::Projection`
retains spend separately; Channel retains it even when outcome encoding
fails. An unrepresentable domain refusal returns Unsupported. The existing
domain-only world retains its explicitly legacy refusal-to-Policy mapping.

Focused byte-peer worlds cover entrance, delayed roots, grant generations,
EOF, output reserve, actual settlement, crossed cleanup and check notices.
The heap world drives maximal entrance data through the real decoder; a
64-seed sweep checks replay and one terminal per host call. Actual HTTP,
SSE/JSON client composition and fake provider document adapters are the
next increment. This checkpoint uses skein d873; HTTP server and SSE writer
modules are available in newer local skein and staged for import after the
gate. TLS awaits resolution of its stream contract; real roots/processes
and manual fresh provider-client comparison remain outstanding.
