# Provider-result anchor

This active, checked-in scenario maps `ai/temper#991` to plan
`ai/temper#992` on `agent/pr-for-feature-991`. It adds a distinct mapping and
does not change the historical `codebase-memory-graph-consumption` mapping or
the active `sequential-graph-evidence` and `result-driven-decision-guidance`
mappings and their frozen relevance criteria.

## Contract

A real Forgejo instance, host Actions runner, standalone Temper process, and
Jig fake engineer execute one small repair. The provider-shaped current-root
fixture mints opaque values only from successful provider results. The live
agent must consume a successful result in a later model turn to select its
result-derived trace and then the current-root implementation and behavioral
sources needed for implementation selection.

Unrelated or conventional substitution and incomplete source evidence cannot
satisfy the fixture. Before mutation, the core decision-anchor policy requires
the consumed trace plus current-root implementation, caller/model, and focused
behavioral-test evidence. The valid path applies one minimal semantic repair,
runs focused host checks, and requires the Forgejo workflow to land the
implementation PR and close the source issue.

## Privacy-safe evidence

The checked-in manifest and aggregate run evidence retain only safe aggregate
tool, ordering, binding, and complete typed V1-correlation facts. Provider
arguments, results, minted values, opaque targets, fixture source paths,
digests, prompts, credentials, and diagnostic traces remain in ephemeral
runtime fixture state and logs.

Run this mapped scenario against the exact feature head, using the validation
path rather than an inherited default-branch scenario. After landing, build a
fresh detached exact-final-head candidate and require the enabled smoke to meet
task correctness, focused host checks, current-root anchor consumption, CI
convergence, and the frozen relevance threshold before the unchanged
