# Result-driven decision guidance

This active, checked-in scenario maps `ai/temper#982` to plan
`ai/temper#983` on `agent/pr-for-feature-982`. It is a new mapping: it does not
change the historical `#962` mapping or the active `#973` mapping and their
frozen relevance criteria.

## Contract

A real Forgejo instance, host Actions runner, standalone Temper process, and a
Jig fake engineer execute one small repair. The provider-shaped current-root
fixture mints opaque values at runtime. The engineer can select each dependent
operation only after consuming the successful predecessor in a later model
turn. This distinguishes genuine result-derived consumption from a scripted
but unrelated successful sequence or producer-turn dependent reads.

Before mutation, the fixture requires consumed current-root implementation,
caller/model, and focused behavioral-test facts. It rejects incomplete,
unrelated, stale, or same-turn consumption. The engineer then applies one
minimal semantic repair, validates it with host checks, and the Forgejo workflow
must land the implementation PR and close the source issue.

## Privacy-safe evidence

The checked-in manifest and aggregate run evidence retain only safe tool names,
aggregate call facts, normalized binding facts, and complete typed V1
correlation facts. Provider arguments, minted values, results, source, targets,
digests, and diagnostic traces stay in ephemeral runtime fixture state and logs.

## Landing use

Run this mapped scenario against the exact feature head. After landing, build a
fresh detached exact-final-head candidate and require an enabled smoke to meet
task correctness, host checks, exact patch, successful current-root evidence,
and the frozen relevance threshold before beginning the unchanged
enabled/disabled/unavailable matrix.

```sh
cargo dev-scenario-check
cargo dev-scenario-run scenarios/result-driven-decision-guidance
```
